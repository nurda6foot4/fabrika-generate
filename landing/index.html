Process

How the pipeline works

Five steps from a text brief to 16 encoded video clips. No manual work between them.

1

Parse the creative brief

The system reads an HTML report exported from Fabrika (Higgsfield's creative planning tool). It extracts the story direction, target audience, 13 scenes with speaker labels, and voiceover lines — then expands each scene into individual clips per speaker so Person A and Person B never share a frame.

Python BeautifulSoup Regex parser
2

Generate two character portraits

Before any video is made, the system creates two reference images — one for each person. Person A: a man, navy t-shirt, home office. Person B: a woman, light grey sweater, home office. These portraits are saved and reused as the "face lock" for every keyframe in the video.

Higgsfield Image API nano_banana_2 9:16 portrait
3

Generate a keyframe per clip

For each of the 16 clips, the system writes a detailed visual prompt — shot type, mood, lighting, environment — and generates a single still image using the matching character portrait as a reference. The system automatically picks Person A's portrait when Person A is speaking, and Person B's when Person B is speaking.

Higgsfield Image API nano_banana_2 Character ref injection
4

Animate each keyframe into a video

Each approved keyframe is sent to the video model with a motion prompt — duration (4s, 6s, or 8s), camera movement, and the voiceover text. The model animates the still image into a live video clip with lip-sync audio.

Higgsfield Video API veo3_1 4–8 second clips
5

Encode, validate and package

Every raw video is transcoded to H.264 1080×1920 (9:16 vertical), validated for resolution and codec, and saved with a JSON sidecar file containing full provenance — prompts used, job IDs, credits spent. Ready to drag into Adobe Premiere.

FFmpeg SQLite job tracker JSON sidecar
Engineering

Problems I ran into
and how I fixed them

Building on a real AI API means dealing with real surprises. Here's what broke and what I did about it.

🖼️

The AI kept making split-screen collages

Every keyframe came back as a 4-panel storyboard — four angles of the same character in one image. Completely unusable for video.

→ Fix

Added explicit "negative" prompts to every image request: no panels, no split screen, no collage, single continuous scene. Also rewrote the character reference workflow to generate single portraits instead of character sheets.

👥

Person A and Person B looked identical

Both characters came out as the same man in a navy shirt. The system was using the same character description for both — because no one told it they should be different people.

→ Fix

Built a separate character description library for each person per format. Person B became a woman with shoulder-length brown hair and a light grey sweater — visually unmistakeable from Person A.

💬

Dialogue lines weren't being assigned to speakers

The original scenes contained lines like Person A: 'text' but the parser ignored them — the speaker labels ended up as leftover junk text in the visual prompt.

→ Fix

Wrote a dedicated dialogue expander that extracts every speaker block using regex, splits long speeches into 8-second clips, and tags each clip with who is speaking — so character ref selection is automatic.

⛔

The pipeline crashed waiting for keyboard input

The pipeline asked "Approve keyframe? y/n" for each clip. When run in the background or unattended, it hit EOFError and died after the first clip.

→ Fix

Added an --auto-approve flag that skips the human checkpoint entirely. Batch runs now complete all 16 clips without interruption.

💸

The budget was razor-thin — no room for trial and error

Claude's $20/month plan has hard context limits. Higgsfield gave me 1,200 credits via a promo code — barely enough if every generation went right. Wrong prompts, parser bugs, and character mismatches burned credits fast with nothing to show for it.

→ Fix

Used RUFLO — an open-source LLM orchestrator — to route tasks to the right model at the right moment, avoiding expensive Claude calls for mechanical work. The LLM Council skill let multiple models cross-check prompts before submitting, catching bad generations before they hit the API and wasted credits.

Stack

What I used

Every tool chosen for a reason — nothing added just to look impressive.

⚡

Higgsfield API

Image generation (nano_banana_2) + video generation (veo3_1). The core engine.

🐍

Python

Pipeline orchestration, HTML parsing, prompt building, scene expansion.

🗄️

SQLite

Tracks every job, clip, cost, and error. Full resume capability if a run is interrupted.

🎞️

FFmpeg

Transcodes raw output to H.264 1080×1920, validates resolution and codec, writes sidecar JSON.

🧠

Claude Code

Used as an agentic coding assistant to build, debug and iterate the full pipeline in real time.

🔀

RUFLO

Open-source LLM orchestrator. Routes tasks to the right model, runs LLM Council cross-checks, and cuts wasted API calls when the budget is tight.

🎬

Adobe Premiere

Final assembly. The pipeline outputs Premiere-ready files — drop in, no re-encoding needed.
